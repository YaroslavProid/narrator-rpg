# Narrator RPG — спецификация (v0.1)

Локальное ролевое приложение с RPG-механикой в основе: «своя замена Talemate». Ведёт рассказчик (Narrator), персонажи говорят через агентов, механика считается кодом.

## 1. Цели и не-цели

**Цели**
- Цельный игровой цикл: игрок пишет действие, приложение отвечает одним связным блоком (повествование + реплики персонажей + продолжение сцены). Рассказчика не нужно вызывать вручную.
- RPG-механика как ядро: статы, навыки, инвентарь, проверки, XP/уровни, бой, команды «Система, …». Всё детерминированно, в коде.
- Долгая память в духе Talemate: векторный поиск, слоистые сводки, факты.
- Быстрота на одном слоте llama.cpp: максимум попаданий в prompt cache за счёт байт-стабильного префикса.
- Всегда русский язык. Мобильный веб-UI (телефон, LAN/Tailscale).
- Взрослый мрачный контент в рамках закона. Модель uncensored, приложение не добавляет своих фильтров.

**Не-цели (пока)**
- Мультиплеер, облачные LLM, TTS, генерация изображений (ComfyUI — позже и не одновременно с LLM).
- Редактор нод/визуальное программирование как в Talemate.
- Поддержка множества бэкендов: только OpenAI-совместимый llama-server.

## 2. Окружение и ограничения

- Windows, RX 9060 XT 16 ГБ, 16 ГБ RAM.
- llama-server (Vulkan), Gemma 4 26B-A4B IQ4_XS, `http://localhost:11435`, `--jinja`, `-np 1`, `-c 36864`, KV q8, reasoning off.
- `--cache-reuse` не работает, поэтому кэш попадает только при совпадении **префикса байт-в-байт**.
- Скорость: PP ≈600 т/с на 9k, ≈300 на 20k, ≈200 на 30k; генерация 54–69 т/с. Промах кэша на 25k токенах обходится в 1.5–2 минуты. Это главный враг.
- Эмбеддинги считаются на CPU маленькой моделью (напр. `multilingual-e5-small` или `paraphrase-multilingual-MiniLM-L12-v2`, ONNX/sentence-transformers).
- Доступ с телефона: Tailscale `100.87.129.25`. Сервер слушает `0.0.0.0:<порт>`. Правило firewall может требовать однократного запуска от администратора (скрипт `setup-firewall.ps1`).

## 3. Архитектура

**Стек:** Python 3.11+, FastAPI + uvicorn, WebSocket для стриминга, Pydantic для моделей и валидации, httpx (async) для llama-server, ChromaDB (persistent) для векторов, Jinja2 для шаблонов промптов, SQLite или JSON-файлы для сохранений. UI: один HTML + vanilla JS/Alpine.js (mobile-first, без сборки).

```
UI (phone) ──WS──> FastAPI
                    ├─ TurnEngine (оркестратор хода)
                    │    ├─ Narrator loop (LLM + протокол инструментов)
                    │    ├─ CharacterAgent.speak (тот же LLM, тот же слот)
                    │    └─ MechanicsEngine (чистый Python, без LLM)
                    ├─ Memory (Chroma + summaries + facts)
                    ├─ PromptBuilder (стабильный префикс, бюджет токенов)
                    ├─ LLMClient (llama-server, стриминг, GBNF/json_schema)
                    └─ SaveStore (сцены, снапшоты)
```

Модули: `engine/turn.py`, `engine/protocol.py`, `mechanics/*.py`, `memory/*.py`, `prompts/*.j2`, `llm/client.py`, `store/*.py`, `web/`.

## 4. Игровой цикл (turn loop)

1. **Ввод игрока.** Если ввод — команда «Система, …» или `/…`, его обрабатывает MechanicsEngine без LLM, ответ печатается сразу (см. §7).
2. **Предварительная механика (опционально).** Код смотрит на ввод и, если явно нужна проверка (атака, взлом, убеждение), ничего не решает сам: решение принимает Narrator через инструмент.
3. **Narrator loop** (не больше N=4 шагов на ход):
   - Narrator генерирует ответ в **текстовом тег-протоколе** (основной вариант, см. §12), например:
     ```
     <narrate>Дождь хлещет по крыше таверны…</narrate>
     <speak who="Сильфа" intent="насмешливо отказать, намекнуть на долг"/>
     <roll skill="Восприятие" dc="12"/>
     ```
   - Парсер идёт по потоку. `narrate` сразу стримится в UI. На теге действия генерация **останавливается** (stop-строка `/>`), и код выполняет действие:
     - `speak(character, intent)` вызывает CharacterAgent (§5), реплика стримится как `Сильфа: …`;
     - `roll/attack/use_skill/use_item/give_xp/change_stat` проверяются по схеме, клампятся и применяются MechanicsEngine;
   - Результат дописывается в историю как **обычный факт в user-сообщении** с явной меткой (не роль `tool`; на 14B роль `tool` игнорировалась. Проверить на Gemma, но по умолчанию использовать user):
     `[СИСТЕМА: результат] Проверка Восприятия: 1d20+3 = 15 против 12 — успех.`
   - Narrator продолжает с того же места (append-only, кэш попадает).
4. **Завершение хода**: тег `<end/>` или лимит шагов. Сборка финального текста:
   ```
   *Дождь хлещет по крыше таверны…*
   Сильфа: Долги, милый, сами себя не отдают.
   *Она отворачивается к стойке. Где-то хлопает дверь.*
   ```
5. **После хода (фоном, пока игрок читает/печатает)**: эмбеддинг хода в Chroma, обновление фактов, при необходимости сводка (§8). Фоновые LLM-вызовы делаются **только когда слот свободен** и ставятся в очередь с приоритетом ниже хода игрока (у слота одна очередь).

Стриминг в UI идёт сегментами: `{type: "narration"|"speech"|"system", who?, delta}`. UI сразу рендерит курсив/реплики.

## 5. Агенты персонажей

- **Карточка**: имя, внешность, характер, манера речи, цели, отношения, примеры реплик. Импорт из Character Card V2/V3 (PNG/JSON) и из персонажей Talemate.
- **speak() = тот же модельный вызов на том же слоте.** Без второго слота и без смены модели. Чтобы не ломать кэш Narrator, **продолжаем тот же промпт**: в конец дописывается user-блок
  `[РЕПЛИКА] Говорит Сильфа. Карточка: … Что она знает: … Намерение: … Ответь одной-тремя фразами от её лица, по-русски, без повествования.`
  Генерация ограничена (`max_tokens≈120`, stop на `\n\n`/`<`). Префикс общий, поэтому заново читается только этот хвост. Потом блок РЕПЛИКА **удаляется из истории**, а в историю попадает только сама реплика. Кэш тратит лишь хвост, и это дешевле второго промпта.
- **Приватная память / знания**: каждое событие истории помечено `witnesses: [ids]` (кто присутствовал в локации, решает код по `scene.present`). В блок «Что она знает» идут только сводки и факты, где персонаж свидетель, плюс его приватные заметки (секреты из карточки, отношения). Это удерживает модель от «всезнания», хотя полной гарантии не даёт.
- Карточки активных персонажей лежат в **стабильной части префикса** (§9), поэтому в блок РЕПЛИКА идёт только ссылка/знания, а не вся карточка. Если персонаж редкий и не входит в префикс, карточку дописываем инлайн.

## 6. Режиссёр (Director): опционально и дёшево

- По умолчанию **выключен как отдельный LLM-вызов.** Его роль выполняют: (а) строки «цели сцены / сюжетные крючки» в стабильном блоке, (б) код, который раз в K ходов (или по триггеру: долгий бой, застой) добавляет user-подсказку `[РЕЖИССЁР] Подними ставки: …` из заранее заданного списка арки.
- Опциональный LLM-режиссёр запускается только в фоне, после сводки, и пишет 2–3 пункта «что дальше» в блок памяти. Каждый ход он не вызывается.

## 7. Движок механики (без LLM)

Перенести концепции модуля «Система» из `scenes\дракония-малфой\nodes` (`system-handle-input`, `system-update-stats`, `system-auto-update`, инъекции в narrator/conversation/director).

- **Статы**: HP/MP/стамина, атрибуты (Сила, Ловкость, Интеллект, Харизма, Восприятие…), настраиваются по сцене (YAML).
- **Навыки**: уровень, связанный атрибут, кулдауны и стоимость.
- **Инвентарь**: предметы с типами, эффектами, количеством, весом (опционально), экипировкой.
- **Проверки**: `d20 + мод(атрибут) + навык против DC`, крит 20/провал 1. RNG с сидом в сохранении (воспроизводимость).
- **Бой**: инициатива, атака против защиты, урон кубиками, состояния (кровотечение, оглушение). Narrator лишь объявляет намерение (`attack target=…`), числа считает код.
- **XP/уровни**: таблица порогов. Level-up даёт очки атрибутов и навыков и выводится сообщением Системы.
- **Дельты от LLM**: если Narrator меняет статы (`<change_stat …/>`) или фоновый «авто-апдейт» предлагает JSON-дельты, то: валидация Pydantic, клампинг (например, |ΔHP| ≤ 30% max за событие, XP ≤ лимит за ход, нельзя создать легендарный предмет из воздуха), лог изменений, отказ при нарушении правил.
- **Команды «Система, …»** (детерминированно, мгновенно): `Система, статус`, `инвентарь`, `навыки`, `квесты`, `распредели очки Сила +1`. Разбор регэкспами и синонимами, ответ по шаблону в стиле LitRPG-окна.
- **Факты механики → в промпт**: компактный блок «Состояние героя» (≤300 токенов) перед недавними ходами. Он меняется, поэтому стоит **после** стабильной части.

## 8. Память

Подход Talemate (memory agent + layered history + world state), реализованный заново:

- **Векторное хранилище**: ChromaDB persistent, коллекция на сцену. Документы: ходы (по сегментам), сводки, факты, выдержки из карточек/лора. Метаданные: `turn`, `type`, `witnesses`, `location`, `characters`. Эмбеддинги на CPU.
- **Слоистые сводки** (как `layered_history.py`): слой 0 — сырые ходы; когда в неархивированном окне ≥ ~3k токенов, старейший кусок сжимается в сводку слоя 1 (~150–250 токенов); когда сводок слоя 1 ≥ 8, они сжимаются в слой 2, и т.д.
- **Факты / world state**: список коротких утверждений («Сильфа должна гильдии 50 золотых», «Таверна сгорела») с id и статусом. Обновляются фоном раз в K ходов или по сводке (LLM предлагает JSON-список add/update/remove, код валидирует).
- **Когда что запускается**: эмбеддинг сразу после хода (CPU, параллельно). Сводка/факты только когда окно переполняется, в фоне, в простое слота. Перед следующим ходом не ждём фон: если он не успел, ход идёт со старым состоянием, а фон отменяется/откладывается.
- **Извлечение**: запрос = ввод игрока + последние 2 хода; top-k=5 с фильтром по witnesses и дедупом против того, что уже есть в промпте.
- **Важно для кэша**: сводки меняются редко и только «скачком» (во время архивации), и именно тогда разовый промах кэша допустим. Извлечённые воспоминания меняются каждый ход, поэтому идут **в конце** (§9).

## 9. Промпты и кэш (single-slot llama.cpp)

**Порядок промпта (байт-стабильный префикс):**

| # | Блок | Меняется | ~Токены |
|---|------|----------|---------|
| 1 | Системный промпт Narrator (роль, протокол тегов, правила языка/стиля) | никогда | 1 200 |
| 2 | Правила механики + карточки игрока и ключевых NPC + лор сцены | почти никогда (смена состава) | 4 000 |
| 3 | Сводки слоёв 2→1 (старые→новые), факты (сорт. по id) | при архивации | 3 000 |
| 4 | Недавние ходы (append-only) | каждый ход дописывается | до 14 000 |
| 5 | Хвост: состояние героя + извлечённые воспоминания + подсказка режиссёра + ввод игрока | каждый ход | 1 500 |
| — | Генерация + speak + результаты | — | 4 000 |
| | **Итого** | | ≈ 28–32k из 36 864 |

Правила:
- Никаких таймстемпов, случайных порядков, счётчиков в стабильных блоках. Сериализация детерминирована (сортированные ключи, фиксированные шаблоны).
- Память **никогда не правит системный промпт**: только блок в хвосте.
- Один Narrator-«шейп» промпта. speak, результаты действий и тег РЕЖИССЁР являются **дописками** к тому же промпту, а не отдельными промптами.
- Хвост (блок 5) ставится как последнее user-сообщение. Чтобы следующий ход попал в кэш, в историю хода 4 сохраняется **только ввод игрока и итоговый ответ**, а хвост выбрасывается. Перечитываться будут хвост + новый ход (~2–3k токенов ≈ 5 с).
- Фоновые задачи (сводка, факты) используют **другой** промпт и вытесняют кэш Narrator. Поэтому: (а) запускать редко, пачкой; (б) после фоновой задачи сразу «прогреть» кэш Narrator запросом `max_tokens=0`/`n_predict=0` на текущем префиксе, пока игрок читает; (в) по возможности оформлять сводку как дописку к промпту Narrator («[АРХИВАТОР] сожми ходы X–Y»), чтобы префикс общий.
- Обрезка недавних ходов идёт **блоками** (архивация 3k за раз), а не по одному ходу, иначе префикс сдвигается каждый ход.
- Перед каждым вызовом считаем токены через `/tokenize` и логируем `cache_n`/`prompt_n` из ответа llama-server (метрика попаданий в UI-отладке).
- Использовать `/completion` с raw-промптом, отрендеренным локальным chat-шаблоном Gemma: полный контроль байтов и возможность продолжать ответ ассистента. `/v1/chat/completions` оставить как запасной вариант.

## 10. Русский язык

- Системный промпт на русском, все шаблоны и примеры на русском, карточки переводятся при импорте (опционально, LLM-задача в фоне).
- Явное правило в блоке 1 и короткое напоминание в хвосте: «Отвечай только по-русски».
- Проверка кода: доля кириллицы в сегменте < 70% → одна повторная генерация сегмента с напоминанием. Имена собственные латиницей допустимы (whitelist).
- Короткие ответы (по умолчанию `max_tokens` хода ≈ 350, настраивается).

## 11. Модель данных и формат сохранений

Папка сцены `data/scenes/<slug>/`:
- `scene.yaml`: название, сеттинг, лор, правила механики, арка/крючки, настройки.
- `characters/<id>.yaml`: карточка + `private_notes` + `is_player`.
- `state.json`: статы, инвентарь, навыки, квесты, локация, `present`, RNG seed, номер хода.
- `history.jsonl`: append-only события `{turn, kind: player|narration|speech|system|roll, who, text, witnesses, location}`.
- `summaries.json`: слои `{layer, from_turn, to_turn, text, witnesses}`.
- `facts.json`, `chroma/` (векторы, можно перестроить из истории).
- `saves/<timestamp>/`: снапшоты state/summaries/facts + указатель на длину history (имя по времени допустимо, в промпт не попадает).
Pydantic-модели совпадают с файлами. Перемотка = откат history до хода N + пересборка Chroma по метаданным `turn`.

## 12. Протокол инструментов и надёжность

- **Основной вариант: текстовые теги** (п.4): устойчивее tool-calling у Gemma, легко стримить и останавливаться (stop-строки).
- **Валидация**: каждый тег парсится в Pydantic-схему. При ошибке делается **один ретрай**: в конец дописывается `[СИСТЕМА: ошибка формата] … Повтори только тег.`, и генерация идёт с **GBNF-грамматикой** (или `json_schema`), ограничивающей ответ одним валидным тегом/JSON. Если и это не помогло, тег пропускается и ход продолжается повествованием.
- Для фоновых JSON-задач (дельты, факты, сводки-метаданные) **всегда** используется `json_schema`/GBNF.
- Нативный tool-calling через `--jinja` проверить в фазе 0 и включить флагом, если он окажется надёжнее.

## 13. UI (mobile-first)

1. **Игра**: лента сообщений (курсив = повествование, «Имя:» = реплика, плашки Системы и бросков), поле ввода, кнопки «Продолжить», «Переписать последний», «Система» (быстрые команды). Стриминг по WS.
2. **Персонаж**: статы, навыки, инвентарь, квесты (из state.json, без LLM).
3. **Сцены**: список, новая сцена из шаблона, импорт карточки/сцены Talemate, сохранить/загрузить/перемотать.
4. **Персонажи**: редактор карточек, кто присутствует.
5. **Память** (отладка): сводки, факты, последние извлечения, правка вручную.
6. **Настройки/отладка**: URL сервера, лимиты токенов, `cache_n/prompt_n`, время PP/генерации, лог сырых промптов.

| Нодовая система | Не переносим. Логика «Системы» — код + YAML-правила. |
| Модуль «Система» (сцена дракония-малфой) | Концепции: команды, клампинг JSON-дельт, level-up, инъекции в промпты. Переносим как код. |
| AHostie (`ahostie-host`) | Переиспользовать нечего. Учитываем урок: результаты инструментов отдаём как помеченный user-текст. |

## 15. Роадмап

- **Фаза 0 — замеры (1–2 дня)**: клиент llama-server; тест байт-стабильности (cache_n), стоимость speak-дописки, роль `tool` против `user` для результатов, тег-протокол против нативного tool-calling у Gemma, GBNF-ретрай.
- **Фаза 1 — MVP**: FastAPI + WS + простой UI; Narrator с тегами `narrate/speak/end`; CharacterAgent; статы/инвентарь/XP, `roll`, команды «Система, статус/инвентарь»; сохранение/загрузка; русский чек; bind 0.0.0.0 + скрипт firewall.
- **Фаза 2 — память**: Chroma (CPU-эмбеддинги), слоистые сводки, факты, witnesses, прогрев кэша после фона.
- **Фаза 3 — механика полностью**: бой, навыки, клампинг дельт, level-up, квесты, экран персонажа.
- **Фаза 4 — удобство**: импорт карточек/сцен Talemate, перемотка/переписывание, редактор памяти, опциональный режиссёр, отладочная панель.
- **Позже**: картинки через ComfyUI (по очереди с LLM), TTS.

## 16. Риски

| Риск | Митигация |
|------|-----------|
| Gemma ненадёжно вызывает инструменты / ломает формат | Тег-протокол, stop-строки, GBNF/json_schema, один ретрай с ошибкой, деградация в чистое повествование. |

## 18. Решения (21.10.2026)

- **Лицензия: AGPL-3.0.** Проект приватный; заимствовать код Talemate разрешено.
- **Режим правил** (проверки d20 с бросками / только статы «Системы») — переключатель на уровне сцены, выбирается **только при создании сцены** и потом не меняется.
- **Импорт Talemate** — пока не делаем.
- **Число NPC** — сколько нужно по сюжету. Карточки динамические: в фиксированном блоке только присутствующие персонажи + короткий ростер остальных.
- **Бездействие игрока**: достаточно кнопки «Продолжить».
- **Веб-UI на порту 8082** (как у Talemate: уже доступен с телефона и через Tailscale без правила firewall). Приложение не работает одновременно с Talemate.
- **Не запускать веб-UI**, пока у пользователя нет прямого доступа к ПК.

### Фаза 3 (23.10.2026)
- **Архивация не блокирует игрока:** фоновая сводка проверяет `bg_cancel`; ход игрока всегда забирает слот. Re-warm пропускается, если игрок уже ждёт. Несколько блоков архивируются **одним** LLM-вызовом (multi-block JSON); минимальный размер блока `ARCHIVE_MIN` (1500 ток.).
- **Поиск памяти:** гибрид — keyword по фактам + вектор (факты/сводки и события), re-rank по kind/свежести/пересечению слов, дедуп по ходам.
- **Список present:** усилен leave в промпте; авто-leave NPC без активности `INACTIVE_LEAVE` ходов (по умолчанию 5); история и witnesses сохраняются.
- **Бой в коде:** инициатива, `<attack>`, КБ, урон кубиками, состояния (кровотечение/оглушение/…), `<combat start|end>`, `<condition>`. Режим `система` — без кубиков атаки (10+мод).
- **Инвентарь:** экипировка / снять / использовать / дать через «Система, …»; оружие и броня влияют на атаку и КБ.
- **XP:** +очки атрибутов и +1 очко навыка за уровень («Система, навык X +1»).

### Создание сцены с ИИ (23.10.2026)
- **Без ручного ввода атрибутов** при создании: система правил не обязана быть D&D — игрок задаёт только замысел (заголовок + зерно мира), краткий бриф героя и опционально брифы NPC / число NPC, плюс переключатель `rule_mode` (d20 / система).
- **POST `/api/scenes/generate`** — one-shot вызов LLM (отдельный промпт, `json_schema`, не на hot path игры). Модель заполняет: `setting` (лор + стартовая ситуация), карточку игрока (описание, характер, attrs/skills под выбранный режим, стартовый инвентарь), карточки NPC (description/personality/speech/secrets).
- Нормализация на сервере: clamp attrs 3–18, skills из канонического списка, инвентарь без запрещённых «легендарных» слов. Превью в UI → подтверждение → обычный `POST /api/scenes`.
- Механика остаётся code-driven; ИИ только заполняет листы согласованно с `rule_mode` и тоном сцены. Игровой протокол/кэш не меняется.
